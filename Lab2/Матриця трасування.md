# Traceability Matrix — Steam Platform

## Use Case Descriptions

| ID | Use Case | Description |
|----|-----------|-------------|
| UC_Browse | Browse Games | Гравець переглядає каталог доступних ігор на платформі Steam. |
| UC_Search | Search Games by Tag | Гравець здійснює пошук ігор за тегами, жанрами або ключовими словами. |
| UC_View | View Game Details | Гравець переглядає детальну інформацію про гру: опис, рейтинг, розробника, видавця тощо. |
| UC_Wishlist | Add to Wishlist | Гравець додає гру до списку бажаного для подальшої покупки. |
| UC_Purchase | Purchase Game | Гравець купує гру через платіжну систему, після чого отримує доступ до встановлення. |
| UC_Install | Install Game | Гравець встановлює куплену гру на свій пристрій через Steam-клієнт. |
| UC_Play | Play Game | Гравець запускає гру для проходження, взаємодіє з нею через Steam. |
| UC_Track | Track Playtime | Система відстежує тривалість гри користувача та зберігає статистику. |
| UC_WriteReview | Write Review | Гравець пише відгук про гру після покупки або проходження. |
| UC_ReadReview | Read Reviews | Гравець переглядає відгуки інших користувачів про гру. |
| UC_PubPublish | Publish Game | Видавець розміщує нову гру на платформі Steam для продажу. |
| UC_PubCatalog | Manage Game Catalog | Видавець керує каталогом своїх ігор: редагує опис, ціни, статуси. |
| UC_Payment | Process Payment | Платіжна система обробляє фінансову транзакцію при купівлі гри. |
| UC_SyncCloud | Sync Cloud Data | Система синхронізує дані гравця (збереження, налаштування) із хмарним сховищем. |

## Functional Requirements

| ID | Description |
|----|-------------|
| **FR1** | Система повинна дозволяти користувачам реєструватися та входити до системи. |
| **FR2** | Користувач повинен мати профіль із персональними даними. |
| **FR3** | Геймер повинен мати змогу переглядати каталог ігор. |
| **FR4** | Геймер повинен мати змогу придбати та встановити гру. |
| **FR5** | Геймер може залишати відгуки та оцінки. |
| **FR6** | Розробник може додавати або оновлювати інформацію про гру. |
| **FR7** | Розробник може визначати досягнення гри. |
| **FR8** | Паблішер може публікувати, оновлювати та контролювати ігри. |
| **FR9** | Система повинна відображати рейтинг ігор. |
| **FR10** | Система повинна забезпечувати пошук і фільтрацію ігор. |
| **FR11** | Геймер може додавати ігри до списку бажань. |
| **FR12** | Система повинна забезпечувати безпечну аутентифікацію користувачів. |
| **FR13** | Система повинна вести журнал дій користувачів. |
| **FR14** | Користувач може повідомляти про порушення або некоректний контент. |
| **FR15** | Паблішер може блокувати або видаляти ігри з порушеннями. |
| **FR16** | Система повинна інтегруватися з платіжною системою. |
| **FR17** | Система повинна інтегруватися з хмарним сховищем. |
| **FR18** | Геймер може розблоковувати досягнення під час гри. |
| **FR19** | Система повинна підтримувати управління DLC. |
| **FR20** | Система повинна відстежувати час гри користувача. |

## Non-Functional Requirements

| ID | Description |
|----|-------------|
| **NFR1** | Паролі користувачів повинні зберігатися у хешованому вигляді. |
| **NFR2** | Середній час відповіді не повинен перевищувати 5 секунд при 10 000 користувачах. |
| **NFR3** | Інтерфейс повинен бути зручним, інтуїтивним і мультимовним. |
| **NFR4** | Доступ до персональних даних повинен бути обмеженим. |
| **NFR5** | Архітектура системи має дозволяти горизонтальне масштабування. |
| **NFR6** | Доступність системи має бути не менше 99.7% часу. |
| **NFR7** | У разі збою дані користувачів і оплат повинні зберігатися (деякі втрати даних допустимі).|
| **NFR8** | Передача даних у хмарне сховище має бути зашифрованою. |
